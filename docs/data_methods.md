# Data and partition procedure

The public input is the compressed Tox21 CSV linked by DeepChem's official Tox21 loader: https://deepchemdata.s3-us-west-1.amazonaws.com/datasets/tox21.csv.gz . The downloaded bytes, SHA-256, UTC download timestamp, column list, and actual number of records are retained in `data/raw/source.json`. A pre-existing input without source metadata is explicitly marked as having an unverified download date. No DeepChem label transformer or built-in benchmark split is applied.

RDKit parses SMILES and applies `rdMolStandardize.Cleanup`. Fragments containing at least one carbon atom are eligible; the retained fragment has greatest heavy-atom count, then greatest atom count, with ascending canonical isomeric SMILES resolving ties. `Uncharger` is applied to this fragment, followed by sanitization. Structures without an organic fragment and invalid structures are excluded and logged. Canonical isomeric SMILES defines structure identity; the SHA-256 of this string is the structure ID. Stereoisomers remain distinct identities. Tautomers are not canonicalized, so residual tautomer-related near-duplicates are a limitation. There is no learned preprocessing.

A missing assay label excludes its source record only from that assay. For each structure and assay, observed labels are collected: consistent labels produce one record, and conflicting labels remove the whole structure from that assay. Missing labels do not create a conflict with an observed label. The per-assay table records the zero-based raw CSV source rows contributing to each label. `standardized_source_rows.csv`, `duplicate_groups.csv`, and `exclusions.csv` retain the complete audit trail. Missing-label and structure-exclusion log entries can overlap; the accounting identity in `assay_counts.csv` is nonoverlapping.

All valid unique standardized structures receive binary Morgan fingerprints with radius 2 and 2,048 bits, without chirality. The global fingerprint matrix is uint8 for storage; the modeling pipeline must cast to floating point before any SMOTE operation. Identity preserves stereochemistry while these fingerprints do not. A non-stereochemical Bemis-Murcko scaffold identifies groups; every acyclic structure belongs to the single `__EMPTY__` group.

The prespecified seeds are 17, 42, and 2026. Each assay is split independently after its missing/conflicting labels are removed. Random partitions use two stratified splits: hold out 40%, then divide that holdout equally, producing approximately 60% training, 20% calibration, and 20% testing. Scaffold partitions use only scaffold membership and group size, never activity labels. Unique scaffold names are sorted, then their sizes are multiplied by seeded uniform priorities between 0.5 and 1.5. Groups are processed by decreasing priority and allocated to the partition with largest remaining absolute capacity relative to the 60/20/20 targets; tied capacities favor training, calibration, then test. No compound is discarded and groups are never split. The priority jitter gives seeds influence beyond ties while retaining an approximate largest-first allocation. Actual deviations and class counts are reported.

Three-fold random CV uses shuffled stratification within the training partition. Scaffold CV repeats the group allocator with equal thirds and seed plus 1009, using only training rows. Every training row is assigned one validation fold. CV folds never include calibration or test examples. A single-class partition or CV training/validation fold is an explicit infeasibility error; the code does not retry seeds, silently merge folds, or relax scaffold boundaries based on labels. `split_design.json` is written before model evaluation and documents this deterministic procedure. Structure disjointness is checked for both designs, and scaffold disjointness is checked for the scaffold design; scaffold overlap under random splitting is expected and quantified.

Cache manifests hash raw input, preprocessing or splitting source code, configuration, tested relevant package versions, and every output file. A cache hit requires all file hashes to agree. The training implementation must also key its artifacts to each complete partition manifest and fold membership, preventing reuse across folds or partitions.

## Observed audit and split limitations

The executed download contains 7,831 records. Eight rows fail SMILES parsing and 80 have no carbon-containing fragment, leaving 7,743 structurally eligible source records and 7,524 unique standardized structures. Per-assay cleaning retains 6,957 NR-AR structures (298 positive), 6,278 NR-AhR structures (748 positive), and 5,578 SR-MMP structures (888 positive). Raw label counts match the proposal's preliminary counts.

The giant empty-scaffold and benzene-scaffold groups are assigned to training under the fixed size-based allocation. Consequently, scaffold tests describe performance on the remaining held-out scaffold distribution, not a uniform random draw of all scaffold groups. The same giant groups dominate two of the three training CV folds. One NR-AR scaffold CV validation fold has 14 positive examples, and one NR-AhR fold has 18, for every seed; these are flagged exploratory. Scaffold CV fractions deviate by as much as 7.91 percentage points from equal thirds, while final partition fractions are within 0.015 percentage points of the requested 60/20/20 proportions. No groups were split to improve these figures. This is a material limitation for hyperparameter stability and across-seed interpretation; three seeds do not provide independent replicated datasets.

An independent audit recomputed every one of the 7,524 stored fingerprints, verified all canonical-identifier hashes, reconstructed per-assay duplicate eligibility and label provenance from source rows, checked missing-label logs, and checked all 18 partition manifests for coverage, label alignment, and required isolation. All 37 checks passed; the machine-readable record is `docs/data_verification.json`. Four focused unit tests cover invalid/salt processing, assay-specific duplicate/missing handling, deterministic allocation, and split/CV isolation.

The initially installed RDKit 2026.09.2 raised `RuntimeError: bad any cast` for basic Murcko-scaffold extraction even on simple valid SMILES on this host. It was replaced with tested RDKit 2025.09.3 before preparation. Unexpected runtime errors now stop preprocessing, preventing a library failure from being mislabeled as invalid input.
